# Практическая работа Unity 6. Ключ и закрытая дверь

**Тема:** взаимодействие с предметами и открытие двери по условию.  
**Уровень:** начинающие.  
**Предварительные знания:** GameObject, Transform, Collider, `OnTriggerEnter`, `CompareTag`, простые скрипты C#.  
**Продолжительность:** ориентировочно 60–80 минут.  
**Исходный проект:** уже есть персонаж с `CharacterController` и `PlayerController.cs`, камера с `CameraFollow.cs`, земля с Collider. Скрипты камеры и передвижения не меняем.

## Цель занятия

Научиться создавать взаимодействие между игровыми объектами. Игрок должен найти ключ, подобрать его, подойти к закрытой двери и открыть её клавишей **E**. Без ключа дверь не откроется.

**Итоговая проверка:** без ключа дверь остаётся на месте; после подбора ключ исчезает, в консоли появляется сообщение; при нажатии **E** рядом с дверью она открывается.

---

## Этап 1. Создание закрытой двери

**Задача:** создать препятствие, через которое игрок не сможет пройти.

1. В Unity выберите **GameObject → 3D Object → Cube**.
2. Переименуйте куб в `Door`.
3. Разместите его в проходе между двумя платформами или стенами.
4. Задайте примерный **Scale**: `X = 1.5`, `Y = 2.5`, `Z = 0.3` (подкорректируйте под размер персонажа).
5. Убедитесь, что есть **Box Collider** и у него **Is Trigger = false**.
6. При желании назначьте двери материал коричневого цвета.
7. Запустите игру и попробуйте пройти через дверь. Она должна блокировать персонажа.

**Обсуждение:** почему у основной двери `Is Trigger` выключен? Что произойдёт, если его включить?

> На этом этапе **не добавляйте скрипт**. Сначала убедитесь, что сама преграда работает.

---

## Этап 2. Создание ключа

**Задача:** добавить предмет, который можно найти и подобрать.

1. Создайте объект ключа: импортируйте готовую модель либо соберите простую форму из кубов (длинный стержень и небольшая головка). Для учебного примера допустим и один жёлтый Cube.
2. Назовите корневой объект `Key`.
3. Разместите его над землёй так, чтобы игрок мог к нему подойти.
4. На объект `Key` добавьте **Box Collider** (или другой подходящий Collider).
5. Включите **Is Trigger = true**.
6. В Player (`character-digger`) проверьте **Tag = Player**, а также наличие `CharacterController`.

**Важно:** скрипт подбора должен висеть на том же объекте, где расположен триггер, либо код придётся адаптировать под дочерние коллайдеры. Если ключ составлен из нескольких моделей, удобно поместить их внутрь родительского объекта `Key`, а Collider и скрипт оставить на родителе.

### Первый вариант `KeyPickup.cs`: ключ просто исчезает

Создайте скрипт `KeyPickup.cs`, добавьте его на объект `Key`:

```csharp
using UnityEngine;

public class KeyPickup : MonoBehaviour
{
    private void OnTriggerEnter(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            Debug.Log("Ключ подобран!");
            Destroy(gameObject);
        }
    }
}
```

**Проверьте:** при касании игрока ключ исчезает. Обратите внимание, что пока игра **не запоминает**, был ли получен ключ.

**Разбор:** `OnTriggerEnter` выполняется при попадании другого коллайдера в зону триггера; `CompareTag` проверяет игрока; `Destroy` удаляет предмет.

---

## Этап 3. Сохраняем информацию о ключе у игрока

**Проблема:** ключ исчез, но дверь не знает, что игрок его подобрал.

**Решение:** создадим небольшой компонент `PlayerKey.cs`, который будет хранить состояние ключа.

1. В папке `Assets/Scripts` создайте скрипт `PlayerKey.cs`.
2. Напишите:

```csharp
using UnityEngine;

public class PlayerKey : MonoBehaviour
{
    public bool hasKey = false;

    public void CollectKey()
    {
        hasKey = true;
        Debug.Log("Теперь у игрока есть ключ!");
    }
}
```

3. Прикрепите `PlayerKey.cs` к **корневому объекту игрока**, на котором находятся `CharacterController` и `PlayerController`.
4. В Inspector убедитесь, что **Has Key** изначально выключен (`false`).

### Обновляем `KeyPickup.cs`

Теперь при подборе ключа нужно обратиться к компоненту игрока.

**Полностью замените код `KeyPickup.cs` на:**

```csharp
using UnityEngine;

public class KeyPickup : MonoBehaviour
{
    private void OnTriggerEnter(Collider other)
    {
        if (!other.CompareTag("Player"))
            return;

        PlayerKey playerKey = other.GetComponent<PlayerKey>();

        if (playerKey == null)
            return;

        playerKey.CollectKey();
        Destroy(gameObject);
    }
}
```

**Проверка:** войдите в Play Mode, выберите игрока в Hierarchy и посмотрите компонент `Player Key`. После подбора предмета флажок **Has Key** должен стать активным.

**Разбор:** `GetComponent<PlayerKey>()` находит компонент у игрока; `null` означает, что компонент не найден. `return` прекращает дальнейшее выполнение метода.

---

## Этап 4. Создаём зону взаимодействия возле двери

**Задача:** игрок сможет нажать **E**, только когда стоит рядом с дверью.

У двери будут **два разных коллайдера**:

- Основной `Door` с обычным `Box Collider` (`Is Trigger = false`) — физически закрывает проход.
- Дочерний `InteractionZone` с `Box Collider` (`Is Trigger = true`) — определяет, что игрок подошёл к двери.

### Настройка Hierarchy

```text
Door                       (Cube, Box Collider: Is Trigger = false)
└── InteractionZone        (Empty GameObject, Box Collider: Is Trigger = true)
```

**Как создать:**

1. Выберите `Door`.
2. Нажмите правой кнопкой мыши → **Create Empty**.
3. Назовите объект `InteractionZone`.
4. Установите **Local Position = (0, 0, 0)**.
5. Добавьте **Box Collider**, включите **Is Trigger**.
6. Настройте **Size** относительно двери, например `X = 3`, `Y = 3`, `Z = 3`. Зона должна выступать перед дверью, чтобы игрок мог в неё войти, не проходя сквозь дверь.
7. При необходимости добавьте на `InteractionZone` компонент **Rigidbody**: `Is Kinematic = true`, `Use Gravity = false`. Это помогает обеспечить стабильное срабатывание триггеров. На саму дверь физический Rigidbody не нужен.

> Если используется импортированная модель двери, её основному коллайдеру всё равно необходимо оставаться непроходимым. Не ставьте `Is Trigger` на основной коллайдер двери.

---

## Этап 5. Создаём скрипт открытия двери

**Задача:** проверить, что игрок рядом, и реагировать на нажатие клавиши **E**.

1. Создайте скрипт `DoorInteraction.cs`.
2. Прикрепите его к объекту **InteractionZone**, не к двери.
3. Используйте следующий код:

```csharp
using UnityEngine;

public class DoorInteraction : MonoBehaviour
{
    public GameObject door;

    private PlayerKey playerKey;

    private void OnTriggerEnter(Collider other)
    {
        if (!other.CompareTag("Player"))
            return;

        playerKey = other.GetComponent<PlayerKey>();
        Debug.Log("Нажмите E, чтобы открыть дверь");
    }

    private void OnTriggerExit(Collider other)
    {
        if (other.CompareTag("Player"))
        {
            playerKey = null;
        }
    }

    private void Update()
    {
        if (playerKey == null)
            return;

        if (!Input.GetKeyDown(KeyCode.E))
            return;

        if (playerKey.hasKey)
        {
            Debug.Log("Дверь открыта!");
            door.SetActive(false);
        }
        else
        {
            Debug.Log("Дверь закрыта. Сначала найдите ключ!");
        }
    }
}
```

### Настройка Inspector

1. Выберите `InteractionZone`.
2. В компоненте `Door Interaction (Script)` найдите поле **Door**.
3. Перетащите **родительский объект `Door`** из Hierarchy в это поле.
4. Убедитесь, что скрипт `DoorInteraction` висит на `InteractionZone`, а не на отключаемом объекте, который уже выключен в начале игры.

**Почему используются три метода?**

- `OnTriggerEnter` — игрок подошёл к двери.
- `OnTriggerExit` — игрок отошёл от двери.
- `Update` — проверяем нажатие клавиши E каждый кадр, пока игрок рядом. Это надёжнее, чем проверять `GetKeyDown` только внутри `OnTriggerStay`.

**Почему `door.SetActive(false)`?** Для первого занятия проще сделать так, чтобы дверь исчезала и освобождала проход. В дальнейшем можно заменить исчезновение на анимацию открытия.

## Этап 6. Проверяем игру по сценариям

### Сценарий А. Игрок без ключа

1. Нажмите Play.
2. Не подбирая ключ, подойдите к двери.
3. Нажмите **E**.
4. В Console ожидается сообщение: `Дверь закрыта. Сначала найдите ключ!`.
5. Убедитесь, что через дверь пройти нельзя.

### Сценарий Б. Игрок с ключом

1. Начните игру заново.
2. Подойдите к ключу, чтобы подобрать его.
3. У игрока в Inspector должно измениться `Has Key = true`.
4. Подойдите к двери и нажмите **E**.
5. Дверь должна исчезнуть, освободив проход.

### Сценарий В. Игрок далеко от двери

1. Подберите ключ.
2. Отойдите далеко от двери.
3. Нажмите **E**.
4. Дверь **не должна** открыться: игрок не находится в `InteractionZone`.

## Этап 7. Самостоятельные задания

1. Поменяйте цвет двери, чтобы было сразу понятно, что она закрыта.
2. Добавьте ещё одну дверь, которая открывается тем же ключом.
3. Сделайте ключ другого цвета и разместите его на высокой платформе.
4. **Дополнительное задание:** добавьте второй ключ. Измените систему так, чтобы каждая дверь открывалась своим ключом (потребуется хранить не просто `bool`, а идентификатор ключа либо несколько отдельных состояний).

## Типичные ошибки и способы исправления

| Проблема | Возможная причина | Что проверить |
|---|---|---|
| Ключ не исчезает | Триггер не срабатывает | `Is Trigger = true`, коллайдер игрока, Tag = `Player` |
| Ключ исчезает, но `Has Key` не меняется | `PlayerKey` отсутствует или находится на другом объекте | Скрипт на том же корневом объекте, который имеет тег `Player` |
| Игрок проходит через закрытую дверь | Основной коллайдер двери триггерный или отключён | На `Door` должен быть обычный Collider, `Is Trigger = false` |
| Нажатие E ничего не делает | Игрок не вошёл в `InteractionZone` | Размер и положение зоны, `Is Trigger = true`, ссылки в Inspector |
| Unity выдаёт `NullReferenceException` | Не назначена ссылка `Door` или `PlayerKey` | Перетащите `Door` в поле `Door`; проверьте компонент на игроке |
| `Input.GetKeyDown` не работает | Проект настроен только на новый Input System | В **Edit → Project Settings → Player → Active Input Handling** включите `Both` либо используйте старый Input Manager, как в текущих уроках |
| Дверь открывается, но персонаж не может пройти | Проход перекрыт другим коллайдером | Проверьте стены, землю и дополнительные коллайдеры |

## Итог занятия

К концу работы в проекте должны быть:

```text
Scene
├── Player (CharacterController, PlayerController, PlayerKey)
├── Main Camera (CameraFollow)
├── Key (Collider: Is Trigger, KeyPickup)
├── Door (Box Collider: Is Trigger = false)
│   └── InteractionZone (Box Collider: Is Trigger, DoorInteraction)
└── Ground (Collider)
```

**Главный результат:** игрок может подобрать ключ; информация о ключе хранится в компоненте игрока; дверь открывается по **E** только рядом с ней и только после получения ключа. При этом существующие скрипты камеры, движения, монет и здоровья не изменяются.

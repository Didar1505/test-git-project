# Unity — урок №6. Камера, двойной прыжок и скользкие поверхности

> **Адаптированная методичка** по уроку №6 «Камера, прыжки, скольжение». Оставлены все три темы, но исправлены две проблемные механики: вращение и скольжение. **Именно в конце этого занятия** получится управление камерой и персонажем, которое уже понравилось нам в работающем проекте.

**Рекомендуемое время:** 80–100 минут (с дополнительным временем на игровое тестирование).  
**Итог:** камера вращается мышью вокруг героя; WASD двигает относительно взгляда камеры; герой поворачивается к направлению ходьбы; можно прыгнуть два раза; на платформах с тегом `Slippery` сохраняется инерция.

## 2. Исправляем управление камерой

**Проблема старой версии из материала:** мышь вращает саму модель героя с очень высокой чувствительностью (`1000`), затем камера пытается догнать поворот. В результате камера резко уходит за героя, и его бывает трудно увидеть. Переменная `xRotation` также не использует `Mouse Y` для настоящего наклона камеры.

**Наше решение:** мышь вращает **только камеру** вокруг игрока (`yaw`/`pitch`), а персонаж смотрит туда, куда идёт при нажатии WASD. Так две системы не спорят за поворот одного и того же объекта.

### Замените CameraFollow.cs целиком

```csharp
using UnityEngine;

public class CameraFollow : MonoBehaviour
{
    [Header("Target")]
    public Transform target;

    [Header("Camera Settings")]
    public float distance = 4.5f;
    public float height = 1.5f;
    public float smoothSpeed = 10f;

    [Header("Mouse Settings")]
    public float mouseSensitivity = 2f;
    public float minPitch = -20f;
    public float maxPitch = 65f;

    private float yaw;
    private float pitch = 20f;

    void Start()
    {
        if (target == null) return;

        yaw = target.eulerAngles.y;
        UpdateCameraPosition(true);
    }

    void LateUpdate()
    {
        if (target == null) return;

        yaw += Input.GetAxis("Mouse X") * mouseSensitivity;
        pitch -= Input.GetAxis("Mouse Y") * mouseSensitivity;
        pitch = Mathf.Clamp(pitch, minPitch, maxPitch);

        UpdateCameraPosition(false);
    }

    void UpdateCameraPosition(bool instant)
    {
        Quaternion rotation = Quaternion.Euler(pitch, yaw, 0f);
        Vector3 lookTarget = target.position + Vector3.up * height;

        Vector3 desiredPosition = lookTarget
            - rotation * Vector3.forward * distance;

        if (instant)
        {
            transform.position = desiredPosition;
        }
        else
        {
            float t = 1f - Mathf.Exp(-smoothSpeed * Time.deltaTime);
            transform.position = Vector3.Lerp(
                transform.position,
                desiredPosition,
                t
            );
        }

        transform.LookAt(lookTarget);
    }
}
```

### Объяснение для учащихся

| Строка/понятие | Назначение |
|---|---|
| `yaw` | Горизонтальный угол камеры: вращение мыши вправо-влево |
| `pitch` | Вертикальный угол камеры: мышь вверх-вниз |
| `mouseSensitivity` | Насколько сильно реагирует камера на движение мыши |
| `Mathf.Clamp(pitch, minPitch, maxPitch)` | Запрещает переворачивать камеру через голову героя |
| `Quaternion.Euler(pitch, yaw, 0)` | Создаёт нужный поворот для расчёта позиции |
| `rotation * Vector3.forward * distance` | Вектор, который позволяет ставить камеру на заданном расстоянии вокруг героя |
| `transform.LookAt(lookTarget)` | Камера всегда смотрит в сторону героя |
| `LateUpdate()` | Камера обновляется после перемещения героя |

**Важно:** это не камера «впереди/сзади модели по фиксированному offset». Она **вращается вокруг точки героя**, поэтому герой остаётся в центре кадра во время поворота мышью.

## 3. Двойной прыжок

В прошлый раз прыжок разрешался только при `isGrounded == true`. Теперь введём два новых поля:

```csharp
[Min(1)] public int maxJumps = 2;
private int jumpsLeft;
```

`maxJumps` — сколько прыжков разрешено после приземления. `jumpsLeft` — сколько осталось.

Логика выглядит так:

```csharp
if (isGrounded)
{
    jumpsLeft = maxJumps;
    if (verticalVelocity < 0f)
        verticalVelocity = -2f;
}

if (Input.GetButtonDown("Jump") && jumpsLeft > 0)
{
    verticalVelocity = Mathf.Sqrt(jumpHeight * -2f * gravity);
    jumpsLeft--;
}
```

**Проверка:** после приземления доступны два прыжка; на третье нажатие в воздухе герой не реагирует. После следующего приземления попытки снова доступны.

## 4. Настоящее скольжение на льду

В исходном уроке предлагается сделать так:

```csharp
// Так делать НЕ будем:
// velocity.x *= 1.2f;
```

У нас прежняя `velocity` обслуживала главным образом вертикальное движение, поэтому умножение её X-компоненты не создаёт физически понятного скольжения. Кроме того, увеличение скорости в обработчике столкновения может приводить к непредсказуемому поведению.

**Идея исправления:** храним горизонтальную скорость отдельно — `horizontalVelocity` — и плавно изменяем её через `Vector3.MoveTowards`. На обычной земле ускорение большое: герой быстро останавливается. На льду ускорение маленькое: герой дольше разгоняется, поворачивает и скользит после отпускания клавиш.

```csharp
horizontalVelocity = Vector3.MoveTowards(
    horizontalVelocity,
    desiredVelocity,
    acceleration * Time.deltaTime
);
```

Узнавать тип поверхности будем с помощью луча вниз (`Physics.Raycast`) и тега **Slippery** на коллайдере земли. Проверка выполняется только если персонаж стоит на земле.

### Подготовьте ледяную платформу

1. На сцене выберите **один** остров, предназначенный для скольжения, или добавьте отдельную широкую платформу.
2. Убедитесь, что у неё есть **не-триггерный** `Box Collider` (или подходящий `Mesh Collider`).
3. В Inspector в поле `Tag` выберите **Add Tag…**, нажмите `+`, создайте тег с точным названием **`Slippery`**.
4. Вернитесь к объекту платформы и назначьте ему тег `Slippery`.
5. Если коллайдер расположен на **дочернем объекте**, тег нужно установить на **том GameObject, которому принадлежит найденный коллайдер**.
6. Для наглядности смените материал платформы на голубой/ледяной цвет (необязательно для работы скрипта).
7. Убедитесь, что слой площадки не исключён из физических запросов Raycast.

### Полный PlayerController.cs — итог урока №6

Замените **весь** код из урока №5. Никакой второй скрипт `IceController` не нужен.

```csharp
using UnityEngine;

[RequireComponent(typeof(CharacterController))]
public class PlayerController : MonoBehaviour
{
    [Header("Movement")]
    public float speed = 5f;
    public float rotationSpeed = 12f;

    [Header("Slippery Surface")]
    public float iceSpeed = 4f;
    public float groundAcceleration = 18f;
    public float iceAcceleration = 2f;
    public float airAcceleration = 4f;

    [Header("Jump")]
    public float jumpHeight = 2f;
    public float gravity = -9.81f;
    [Min(1)] public int maxJumps = 2;

    [Header("Camera")]
    public Transform cameraTransform;

    private CharacterController controller;
    private Vector3 horizontalVelocity;
    private float verticalVelocity;
    private int jumpsLeft;

    void Start()
    {
        controller = GetComponent<CharacterController>();
        jumpsLeft = maxJumps;

        if (cameraTransform == null && UnityEngine.Camera.main != null)
        {
            cameraTransform = UnityEngine.Camera.main.transform;
        }
    }

    void Update()
    {
        bool isGrounded = controller.isGrounded;

        if (isGrounded)
        {
            jumpsLeft = maxJumps;
            if (verticalVelocity < 0f)
            {
                verticalVelocity = -2f;
            }
        }

        bool onIce = isGrounded && IsStandingOnSlipperySurface();

        float moveX = Input.GetAxisRaw("Horizontal");
        float moveZ = Input.GetAxisRaw("Vertical");
        Vector3 input = Vector3.ClampMagnitude(
            new Vector3(moveX, 0f, moveZ), 1f
        );

        Vector3 desiredDirection = input;

        if (cameraTransform != null)
        {
            Vector3 forward = cameraTransform.forward;
            Vector3 right = cameraTransform.right;
            forward.y = 0f;
            right.y = 0f;
            forward.Normalize();
            right.Normalize();

            desiredDirection = forward * input.z + right * input.x;
            desiredDirection = Vector3.ClampMagnitude(desiredDirection, 1f);
        }

        float currentSpeed = onIce ? iceSpeed : speed;
        float acceleration = !isGrounded ? airAcceleration :
            (onIce ? iceAcceleration : groundAcceleration);

        Vector3 desiredVelocity = desiredDirection * currentSpeed;
        horizontalVelocity = Vector3.MoveTowards(
            horizontalVelocity,
            desiredVelocity,
            acceleration * Time.deltaTime
        );

        if (desiredDirection.sqrMagnitude > 0.01f)
        {
            Quaternion desiredRotation = Quaternion.LookRotation(desiredDirection);
            transform.rotation = Quaternion.Slerp(
                transform.rotation,
                desiredRotation,
                Mathf.Clamp01(rotationSpeed * Time.deltaTime)
            );
        }

        if (Input.GetButtonDown("Jump") && jumpsLeft > 0)
        {
            verticalVelocity = Mathf.Sqrt(jumpHeight * -2f * gravity);
            jumpsLeft--;
        }

        verticalVelocity += gravity * Time.deltaTime;

        Vector3 fullVelocity = horizontalVelocity
            + Vector3.up * verticalVelocity;

        controller.Move(fullVelocity * Time.deltaTime);
    }

    bool IsStandingOnSlipperySurface()
    {
        float rayDistance = controller.bounds.extents.y + 0.3f;
        RaycastHit hit;

        if (Physics.Raycast(
            controller.bounds.center,
            Vector3.down,
            out hit,
            rayDistance,
            Physics.DefaultRaycastLayers,
            QueryTriggerInteraction.Ignore))
        {
            return hit.collider.CompareTag("Slippery");
        }

        return false;
    }
}
```

### Что добавилось по сравнению с уроком №5

- `maxJumps` и `jumpsLeft` — позволяют прыгнуть дважды.
- `horizontalVelocity` — сохраняет инерцию движения по земле.
- `verticalVelocity` — отвечает только за гравитацию и прыжки.
- `IsStandingOnSlipperySurface()` — направляет физический луч вниз от центра капсулы `CharacterController`, находит коллайдер площадки и проверяет его тег.
- `iceAcceleration = 2` вместо `groundAcceleration = 18` — отвечает за главное ощущение льда: медленное торможение и смену направления.
- `airAcceleration = 4` — управление в воздухе несколько слабее, чем на обычной земле.
- `controller.Move(...)` вызывается один раз за кадр для объединённого горизонтального и вертикального движения.

> **Важно про Raycast:** используем коллайдер **пола**, а не просто цвет или имя объекта. Если тег `Slippery` отсутствует в проекте, `CompareTag("Slippery")` может вызывать ошибку. Создайте тег перед проверкой скольжения.

| Тест | Что должно происходить |
|---|---|
| Вращаем мышь без WASD | Камера плавно обходит героя; герой сам не крутится |

| Бежим и отпускаем клавиши на платформе Slippery | Персонаж продолжает скользить некоторое время |

### Диагностика частых проблем

| Наблюдение | Решение |
|---|---|
| Камера снова слишком резкая | Проверьте, что **Mouse Sensitivity = 2**, а старый код вращения героя от Mouse X удалён |
| Камера находится внутри земли | Назначен правильный `Target`, Distance = 4.5, Height = 1.5; нет лишнего скрипта/камеры |
| Мышь не работает | Нажмите в окно Game; проверьте `Active Input Handling` (Both/Old) |
| Лёд не скользит | Тег **Slippery** стоит на GameObject с коллайдером; сам коллайдер есть и `Is Trigger` выключен |
| Герой проваливается | Проверьте коллайдеры платформы и размеры капсулы игрока |
| Можно прыгать бесконечно | Убедитесь, что остался **один** PlayerController и строка `jumpsLeft--` выполняется |
| Inspector показывает старые поля Offset / Smooth Speed = 0.125 | Файл `CameraFollow.cs` не обновился или есть старый компонент `Camera (Script)`; сохраните код, проверьте Console, удалите старый компонент |
